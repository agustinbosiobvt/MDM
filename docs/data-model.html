BVT MDM Data Model

Built from the database migrations in the project folder (0001 to 0008), which define every table, column and foreign key in the mdm schema. 23 tables in four groups (master data, price lists, reference lists, imports and system), plus alembic_version.

PK primary key FK foreign key UK unique ||--o{ one to many ||--o| one to zero or one

1. Master data and price lists

Company, customer and vendor all extend one party row, which holds the code, names, EORI and country. Addresses, contacts, price lists and import templates hang off party, so each has a single real foreign key. A product's price is three levels down: price_list → price_list_line → price_list_line_price.

2. Reference lists

exchange_rate exists for future price and margin comparisons and is empty: the app never converts or stores converted prices.

3. Imports and system

An import job holds an uploaded file until it is committed as a price list. Templates remember a customer's or vendor's column mapping for the next file. Users, sessions and the audit log support sign-in and change history.

Not drawn, to keep the diagrams readable: every table except the reference lists, audit_log and oauth_login_state also has created_at, created_by → app_user, updated_at, updated_by → app_user, is_active (soft delete) and version (edit-conflict check). alembic_version only stores the migration number.
